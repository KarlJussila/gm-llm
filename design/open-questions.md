## Benchmark

### Nothing measures whether a session delivered its plan

A pilot run spent 29 turns on the session plan's secondary discovery tracks and never reached the
centrepiece the plan names, with every thread runner-introduced rather than player-introduced
(Part 7). That breaks no rule in `runner-authority.md` — all the content it played was planned —
and no check sees it, so the run scored *well*: fewer turns covering less ground still means fewer
graded units to divide violations by. Open on two axes: whether plan coverage becomes a check at
all, and whether it belongs at runtime (where the checker sees one turn) or in a post-session stage
gate (where the whole transcript is available, which is where it naturally fits). Coupled to the
denominator question — a coverage measure and a per-word denominator attack the same distortion
from opposite ends. Parked on ROADMAP track **recalibration**.

### Is the score model's 0-point floor calibrated anywhere real?

`scoring.score_violations` maps a penalty *rate* to 0–100 with 0 at 2 points/unit. `benchmark.md`
says outright this is a display calibration to retune once B3 shows where tier 0 lands. Until
the baseline is banked the absolute score means nothing and only deltas are readable — which
is worth stating wherever a score is reported. Parked on ROADMAP track **benchmark** (B3).

### The scripted player's digest is regenerated by hand

After each session's reconcile, the player-facing packet (the `dallid`-style digest injected into
the scripted player) should be rebuilt from the updated player-known layer (`*.knowledge.md` /
`*.state.md` / `*.repertoire.md`), so a multi-session auto-run keeps the player's known-facts +
prior-events digest current. Today it is a hand-merge — done manually for the fixture campaign's
S2→S3 handoff. This is coupled to the player-end contract below (it is the "how it is generated"
half), and it generalizes to a product feature: a real player wants the same "what you know /
what's happened" digest. Parked on ROADMAP track **benchmark**.

### The player-end contract is still loose

BENCHMARK B1 names this a prereq to finalizing the bench: **where** the play packet lives
(root vs `campaign/documents/` — `character_packet` is a stopgap), **how** it is generated
(hand-merged from the player-known layer today), and **how** it is loaded (`fixture.json` for
bench, `--character` for autoplay). One canonical home, one generation path, one load contract.
Parked on ROADMAP track **benchmark**.

## Canon layout

### `sessions/` would read better as per-session directories

The flat `sessions/session-N-{plan,transcript,notes}.md` + `session-N.md` digest + `assessment/`
convention would read more cleanly as per-session folders (`sessions/session-N/…`). Surfaced during
combat's planning work, where the bestiary decision made it moot for stat blocks. It is a large
cross-cutting refactor — the `session-{n}-*` path convention is woven through the orchestrator
modules (planner, status, canon, setup, reconciler, loop, mock), the prompt briefs, several skills,
`canon-conventions` §2, and the tests — so it is its own round whenever it is picked up, never a
rider on adjacent work. Parked on ROADMAP track **docs**.

## Docs / infra

### Should `dev/test_*.py` become real pytest tests?

They are standalone scripts with a homegrown `tmp` helper, so `pytest dev/` yields ~47
collection errors that look like breakage and are not (Part 1). Converting would make the gate
conventional and give a cold session what it will reach for anyway. Against: the gate works,
and changing it is not free. Parked on ROADMAP track **docs**.
